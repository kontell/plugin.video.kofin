# Phase 3 — native movies through public Kodi APIs

Implemented 2026-10-07 on `feat/or-phase3-movies`. The internal API build now synchronizes selected movie/mixed libraries into Kodi's native movie library. The release version remains reserved at `0.90.0`; the public prerelease has not been published. The P1D Piers Flatpak satisfies the approved target requirement; the phase 3 release exit still requires development-repository delivery.

## Implementation

`sync/backends/api/library.py` owns one serialized movie worker. It fetches all selected movie listings before publishing their union, validates page totals and identities, and retains the last complete snapshot on failure. Websocket changes, complete enumeration, explicit removals and repair feed private desired/applied generations. Kodi receives immutable snapshot directories, never an interactive browser result or a partially fetched page.

`store.py` keeps generations, pinned scanner snapshots, native identity caches, expected userdata and durable local edits in Kofin's own SQLite file. A stable server/user namespace and item query URL survive library movement and native-ID replacement. Operations remain pending until public readback confirms their outcome; stale acknowledgements cannot complete newer work. A pending local edit is delivered idempotently before an older server snapshot can overwrite it.

`provider.py`, `metadata.py` and `movies.py` implement scanner listing, `refresh_info`, tombstone-aware `check_exists`, local-metadata source binding, scanning, scalar patches, cast/stream refresh, watched/resume restoration and source teardown. Every native mutation validates both the namespaced unique ID and exact resolver URL. Repair re-resolves replaced IDs. Metadata removals clear keys previously supplied by Kofin and preserve unrelated tags, IDs, ratings and artwork. Kodi controls defaults and fields absent from its public interface; exact stream-flag/authority parity remains open in the ledger.

The service starts native replay independently of server reconnection, then polls and consumes server events. Library settings expose movie/mixed selection; update and repair routes dispatch to the API worker. Native playback and context actions use validated public mappings. Dynamic browsing retains the existing live-server routes and lightweight ListItems. Native TV, music videos, music, collections, downloads and legacy SQL maintenance remain unavailable.

Normal startup requires compatible public capabilities, compatible private backend state and an initially empty video/music library. The private setup marker binds native work to one server/user namespace. The build does not adopt old SQL mappings, clear a user's existing library or silently switch namespaces. Dynamic browsing remains available when native setup is blocked. Use a fresh Kodi profile for a real transition.

## Verification

The complete regression suite passes: **3,686 tests**, including the historical SQL writer schema fixtures and extracted API-package tests. Mypy, Ruff and Black pass. Package checks exclude native SQL modules, reject native database access and installed-file writes, and exercise the scanner callbacks from the actual staged distribution. API and SQL archives both build.

The live target was the user-authorized P1D Flatpak **22.0 beta2, `20260831-e513e0ff-dirty`**. Tests stage the API archive under the separate addon ID `plugin.video.kofin.phase3`, with service auto-start removed and private window properties isolated. The active production addon is preserved. The fixture deliberately prepares its own namespace after testing the nonempty-library refusal; this isolates test content while retaining the normal empty-library gate. The fixture bypasses the runtime checker's dirty-build restriction; the approved Flatpak is accepted for release validation. Native operations use the real Kodi library APIs; an audit hook permits SQLite access only to the fixture's own `kofin.db`.

[`lifecycle.json`](lifecycle.json) records real scanner import, repeat without duplication, scalar and watched/resume patches, refresh with changed native ID and restored userdata, stale provider/rating/tag clearing, real native watched-edit capture, server-echo suppression, partial/offline fetch preservation, owned removal, native playback, stop/completion reports and cleanup. The playback test uses a loopback synthetic Jellyfin protocol server and a generated 12-second clip with the shipped `Api`, resolver and service player. It does not claim production-Jellyfin interoperability coverage beyond the shared regression suite.

The latest measured 101-movie coordinator import took **3.931 seconds**. During the actual scan, live dynamic browsing returned all **101 items in 0.056 seconds**. The two-movie initial lifecycle import took **0.650 seconds**. These are single synthetic-fixture observations, not a production-scale benchmark or a directly comparable replacement for the phase 0 SQL baseline.

Recovery coverage includes interrupted scanner pins, stale acknowledgements, rejected/accepted-but-unapplied RPCs, external ID replacement, partial pagination, a failed second selected library, library movement and concurrent newer local edits. The live process-restart probe stages an unapplied update, pins its snapshot, restarts Kodi, then verifies replay, stable identity, repeat repair and owned cleanup; the passing result is recorded in [`restart.json`](restart.json). `RestartApp()` stalled during shutdown, apparently on a thread from an earlier failed fixture, so the verified Kodi Flatpak was terminated and relaunched. This proves recovery after process termination, not a clean-shutdown guarantee. The corrected playback fixture closes its HTTP server in `finally`. Kodi was responsive and the production Kofin addon enabled after fixture removal.

## Reproduction and remaining release gate

Use `tests/live/or_phase3/drive.py` with a configured kodi-drive target and local `ffmpeg`. Run `deploy`, `run`, then `result`; wait for `complete`, `cleanup` and `foreign_unchanged`. For process recovery run `restart-prepare`, inspect `restart-result` for `prepared`, run `restart`, wait for Kodi readiness, then run `restart-verify` and collect `restart-result`. Finish with `remove`. Private transport configuration stays in kodi-drive's `targets.env`; generated media and raw output stay under gitignored `tests/live/results/or-phase3/`.

The P1D Piers Flatpak is an accepted release-validation target. Its passing lifecycle, recovery and dynamic-browsing results count toward acceptance. Complete any outstanding startup/selection checks on a fresh profile using this Flatpak, then publish `0.90.0` and repeat phase 2 repository routing with the real prerelease. No release tag, GitHub prerelease or repository update was created by this implementation.
